# Known Limitations

## Physics / model
* Quasi-steady hydraulics per time step; no transients, water hammer, pressure waves or
  compressibility. Not a substitute for an industrial hydraulic solver.
* Only series pump lines (TANK → valves → PUMP → valves → TANK) are modelled. Parallel pumps,
  branched or looped piping, pumps in series and tank-to-tank gravity transfers are accepted by
  CRUD and shown in the topology but excluded from hydraulic calculation (reported as model issues
  and topology warnings).
* Constant Darcy friction factor; blockage modelled as a lumped contraction loss.
* Cavitation and dry running are approximated by scaling flow/head when a tank is near empty.
* Efficiency follows an assumed parabolic curve; no power measurement exists, so the
  "performance index" is head-based (measured head / curve head), not a true efficiency.
* Water only (ρ = 1000 kg/m³); volume balance stands in for mass balance.

## Data
* All telemetry is synthetic. Fault magnitudes, durations and noise are generated by documented
  rules; real plants have drift, calibration offsets, correlated noise and operator actions that are
  not fully represented.
* Missing readings are stored as NULL values (historian "no data" rows) so the full dataset has
  exactly 100,000 rows; absent timestamps are also detected when telemetry is ingested sparsely.
* The replay "Live Monitoring" page steps through the stored dataset; there is no streaming ingestion.

## Detection & evaluation
* Rule thresholds were chosen from the documented noise model, so detection on the synthetic data is
  strong for faults above the thresholds. Faults below the thresholds (detection-limit tests) are missed
  by design — these are the honest false negatives in the evaluation. Results on real plant data would
  differ and thresholds would need tuning.
* Evaluation is window-based (6 h windows per issue type and asset). Different windowing changes the
  TN count and therefore accuracy; precision/recall/F1 are less sensitive.
* Flow reconciliation needs the downstream (or upstream) tank level sensor to be healthy; when it is
  unavailable a flow imbalance defaults to LEAK with "reconciliation unavailable" in the evidence.
* Blockage is attributed to the longest discharge pipe of the line (the transfer main); the exact
  location along a multi-pipe line is not resolved.

## Application
* No authentication/authorisation; the `actor` on alarm actions is free text. Not production-hardened.
* SQLite is single-writer; suitable for a local demo, not concurrent multi-user production.
* Simulation runs execute synchronously in the request (a 96-step run takes well under a second;
  672 steps a few seconds).
* Re-running `generate_data` resets the database (simulations, alarms and history are cleared).
